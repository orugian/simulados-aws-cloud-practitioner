# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Static HTML/CSS/JS with no build step and no server. It opens by double-click (`file://`) and is also published on GitHub Pages. This is the same model as the user's previous AIF-C01 project (github.com/orugian/simulados-aws-ai-practicioner).

## Users

One candidate studying for the AWS Certified Cloud Practitioner (CLF-C02), exam on 26/11/2026. They take full timed practice exams that simulate exam day and use a study mode to learn from mistakes. They use it on a desktop and occasionally on a phone, in long sessions of up to 90 minutes.

## Product Purpose

Exam simulations that are faithful to the CLF-C02 exam guide v1.3:
- 65 questions, 90 minutes, weights 16/19/22/8 per domain;
- single-choice and multiple-response questions only.

Each simulation is followed by a per-alternative explanation. Success means arriving at the exam knowing your weak domains and having closed them.

## Positioning

A sanitized and validated question bank of 405 questions. The bank carries:
- current naming (support plans Business Support+ / Unified Operations, Amazon Quick, WorkSpaces Applications);
- an out-of-scope list from the official guide;
- answer keys reviewed adversarially.

On top of it:
- 6 fixed exams with no repeated questions;
- random exams stratified by domain;
- a mistakes notebook.

## Operating Context

- Exam mode: no feedback, can flag questions for review, review screen before submitting, auto-submit when time runs out.
- Study mode: immediate correction.
- Progress lives in the browser's localStorage, with JSON export/import.
- Personal strike-through annotations: in exam and study modes any answer option can be crossed out/restored (including correct, selected, and already graded options) via right-click anywhere on the alternative, or Shift + its displayed letter (Shift+F10 / the native context-menu key also work on the focused alternative). Do not add separate strike/restore buttons or consume left-clicks; suppress the browser's context menu only on alternatives of an active question. This never changes selection, answerability, grading or score. Store original option indices separately under each question ID in the session's `riscadas`; preserve across navigation, reload, export/import and in the completed attempt's answer key. New attempts start clear; legacy sessions lazily initialize annotations.

## Capabilities and Constraints

- Data source: `banco/questoes.js` (`window.BANCO`) and `banco/simulados.js` (`window.SIMULADOS`), generated by `tools/validar-banco.js` and `tools/gerar-simulados.js`.
- Must work offline: self-hosted fonts, no CDN.
- Questions in PT-BR with service names in English.
- No ordering or matching question types (they don't exist in CLF-C02).
- At the user's request, full exam results show an explicitly labeled estimated score on the 100–1000 scale with 700 as a reference threshold, alongside raw percentage. The simulator uses its own disclosed linear conversion: round(100 + 900 × correct / total). AWS does not publish its raw-to-scaled conversion; this is not the official psychometric score or a prediction of passing. All simulator questions count (no arbitrary removal of 15 questions). Study mode retains raw percentage. Historical attempts derive the same estimate without resetting progress.

## Evidence on Hand

Real bank of 405 questions with justifications (`banco/`), official guide (`docs/01-escopo-oficial-clf-c02.md`). There is no real performance data: history only exists once the user takes exams.

## Product Principles

1. Faithful to the real exam first: what the exam does not do, the exam mode does not do either.
2. Every mistake has to teach something: per-alternative justification and a mistakes notebook.
3. Honest about the score: label the simulator's 100–1000 conversion as an estimate, disclose its formula and limitations, retain raw percentage and distinguish the 80% training target from the 700-point reference threshold.
4. Zero friction: opens with a double-click, resumes where it left off.

## Accessibility & Inclusion

- Full keyboard use: A–E, arrow keys, M, Enter.
- Correct/incorrect never depends on color alone; icon and text label are always present.
- Contrast ≥ 4.5:1.
- `prefers-reduced-motion` is respected.
